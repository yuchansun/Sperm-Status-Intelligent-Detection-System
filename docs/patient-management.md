# 病患修改與刪除

完成 001–004 後，於 Supabase SQL Editor 執行 `supabase/migrations/202610200005_patient_management.sql` 全部內容，再重新整理本機網站。可重複執行。

在病患歷史頁，或搜尋／讀卡後的檢測前確認區，使用「修改病患資料」或「刪除病患」。沒有檢測紀錄的病患也可從搜尋選取後管理。

修改涵蓋姓名、身分證／病歷識別碼、出生日期、電話、Email、健保卡卡號，不改動內部 UUID、patient_code 或檢測關聯，也不改寫既有報告快照。修改識別碼會阻擋其他有效病患已使用的值，並比對更新時間避免覆蓋他人修改。

刪除需確認，為 patients 新增 deleted_at、deleted_by，採軟刪除，不實際移除病患、檢測、備註、報告、寄送紀錄或私有檔案。介面查詢會排除已刪病患及其檢測，包含搜尋、讀卡比對、歷史與統計。選取後被刪除的病患不可再建立新檢測。刪除不釋放儲存空間，尚未提供還原介面。相同識別碼若對應已刪除資料，請由管理者確認，不會自動還原或合併。

沿用已登入人員共用的 SELECT／UPDATE 權限，未新增實體 DELETE 權限。後續後端亦須排除 deleted_at 非空的病患與檢測。
